# 섹션 1. Introduction

## 1.1 MCP란? (Introducing MCP)

**한 줄 요약:** MCP는 Claude에게 도구와 컨텍스트를 연결해주는 통신 표준. 도구를 매번 직접 코딩하는 수고를 없애준다.

**쉬운 설명**
- 구조: **MCP 클라이언트 ↔ MCP 서버**. 서버 안에 **도구(tools)·리소스(resources)·프롬프트(prompts)** 가 들어 있다.
- 기존 방식의 문제: GitHub 같은 서비스를 붙이려면 개발자가 **도구 스키마와 실행 함수를 일일이 직접 작성·관리**해야 했다. 기능 많은 서비스일수록 부담이 큼.
- MCP의 해법: 그 도구 정의·실행을 **전용 MCP 서버로 떼어낸다.** MCP 서버 = 외부 서비스를 감싼 인터페이스(미리 만들어진 도구 묶음).
- 핵심 이득: 개발자가 도구 스키마·함수를 직접 안 짜도 됨. **누군가(보통 서비스 제공사)가 공식 MCP 서버를 만들어 배포**.

**자주 묻는 것**
- 누가 MCP 서버를 만드나? → 누구나 가능하지만, 보통 서비스 제공사가 공식 구현을 냄.
- 직접 API 호출과 뭐가 다른가? → 미리 만든 도구 스키마·함수를 제공해 **개발 시간을 절약**.
- tool use와의 관계? → 둘은 **같은 게 아니라 상호보완.** MCP는 "도구를 *누가* 만드느냐"에 초점.

**cli_project 연결:** 이 강의 프로젝트는 학습 목적상 클라이언트·서버를 **둘 다** 만든다. 실무에선 보통 한쪽만 구현한다.

## 1.2 MCP 클라이언트 (MCP Clients)

**한 줄 요약:** MCP 클라이언트는 내 서버와 MCP 서버 사이의 통신 창구. 도구를 직접 실행하지 않고 "전달"만 한다.

**쉬운 설명**
- **Transport agnostic(전송 방식 무관):** stdin/stdout, HTTP, WebSocket 등 여러 방법으로 통신 가능. 흔한 구성은 같은 컴퓨터에서 **stdin/stdout**.
- 통신은 MCP 스펙으로 정해진 메시지 교환. 핵심 메시지:
  - **list tools** request/result → 서버에 "도구 뭐 있어?" 묻고 목록 받기
  - **call tool** request/result → "이 도구를 이 인자로 실행해줘" 요청하고 결과 받기

**전형적 흐름**
```
사용자 질문 → (내) 서버가 MCP 클라이언트에 도구 목록 요청
→ 클라이언트가 MCP 서버에 list tools 요청 → 도구 목록 받음
→ 질문 + 도구를 Claude에게 전송 → Claude가 도구 실행 요청
→ 클라이언트가 MCP 서버에 call tool 요청 → 서버가 실제 실행(예: GitHub API)
→ 결과가 체인을 거슬러 돌아옴 → Claude가 최종 답변 → 사용자에게 전달
```

**핵심:** 클라이언트는 **중개자**다. 도구를 자기가 실행하지 않고, 내 코드와 실제 실행 주체(MCP 서버) 사이 통신만 이어준다.

**cli_project 연결:** `mcp_client.py`가 바로 이 중개자. `core/chat.py`(루프)가 도구 목록·실행을 클라이언트에 요청한다.

## 2.2 도구 정의 (Defining Tools with MCP)

**한 줄 요약:** `@mcp.tool` 데코레이터로 함수를 도구로 만든다. JSON 스키마는 SDK가 자동 생성.

**쉬운 설명**
- Python SDK가 **수동 JSON 스키마 작성을 없애줌** — 데코레이터 + 타입 힌트 + `Field` 설명만 쓰면 스키마 자동 생성.
- 문서 저장: `doc_id`를 key로 하는 메모리 dict.
- **도구 1 `read_doc_contents`:** `doc_id` 받아 내용 반환. 없으면 `ValueError`.
- **도구 2 `edit_document`:** `doc_id`, `old_string`, `new_string` 받아 find/replace. 존재 검증 포함.
- 패턴: 데코레이터 → 함수 정의 → 파라미터 타이핑 → 검증 → 핵심 로직.

**핵심 코드**
```python
from pydantic import Field

@mcp.tool(name="read_doc_contents", description="Read the contents of a document and return it as a string.")
def read_document(doc_id: str = Field(description="Id of the document to read")):
    if doc_id not in docs:
        raise ValueError(f"Doc with id {doc_id} not found")
    return docs[doc_id]

@mcp.tool(name="edit_document", description="Edit a document by replacing a string ...")
def edit_document(
    doc_id: str = Field(description="..."),
    old_str: str = Field(description="..."),
    new_str: str = Field(description="..."),
):
    if doc_id not in docs:
        raise ValueError(f"Doc with id {doc_id} not found")
    docs[doc_id] = docs[doc_id].replace(old_str, new_str)
```

**cli_project 연결:** `mcp_server.py`의 TODO "read a doc / edit a doc"가 이 두 도구. (실습 1 FastAPI의 Pydantic·자동 스키마와 같은 발상)

# 섹션 3. 클라이언트 연결 (Connecting with MCP Clients)

## 3.1 클라이언트 구현 (Implementing a Client)

**한 줄 요약:** 세션(연결)을 감싼 래퍼 클래스. `list_tools`/`call_tool`로 서버 기능을 코드에 노출한다.

**쉬운 설명**
- **MCP Client** = 세션을 감싼 클래스 (연결·정리 자동화).
- **Client Session** = SDK가 제공하는 실제 연결. 닫을 때 cleanup 필요 → 그래서 클래스로 감싼다.
- 두 핵심 함수는 **세션에 일을 떠넘기는 얇은 래퍼**.

**핵심 코드**
```python
async def list_tools(self) -> list[types.Tool]:
    result = await self.session().list_tools()
    return result.tools

async def call_tool(self, tool_name: str, tool_input):
    return await self.session().call_tool(tool_name, tool_input)
```

**흐름:** 앱이 도구 목록 요청 → `list_tools` → Claude가 도구·인자 선택 → `call_tool`로 실행 → 결과를 Claude에 반환.

**cli_project 연결:** `mcp_client.py`의 TODO. 채운 뒤 `uv run mcp_client.py`로 연결·도구 목록을 확인하고, `uv run main.py`로 전체 동작 ("report.pdf 내용 뭐야?").

## 3.2 리소스 정의 (Defining Resources)

**한 줄 요약:** Resources = 서버가 **읽기용 데이터**를 노출하는 기능. HTTP의 GET과 같다.

**쉬운 설명**
- 두 종류:
  - **Direct(정적):** 고정 URI (예: `docs://documents`)
  - **Templated(템플릿):** 파라미터 URI (예: `docs://documents/{doc_id}`)
- 흐름: 클라이언트가 URI로 read resource 요청 → 서버가 URI에 맞는 함수 실행 → 결과 반환.
- 구현: `@mcp.resource` + URI + `mime_type`(`application/json`/`text/plain` 등). 템플릿 URI의 `{param}`은 **함수 인자로 자동 전달**. 반환값은 SDK가 **자동 직렬화**.

**핵심 코드**
```python
@mcp.resource("docs://documents", mime_type="application/json")
def list_docs() -> list[str]:
    return list(docs.keys())               # 목록 (Direct)

@mcp.resource("docs://documents/{doc_id}", mime_type="text/plain")
def fetch_doc(doc_id: str) -> str:         # 단건 (Templated)
    if doc_id not in docs:
        raise ValueError(f"Doc with id {doc_id} not found")
    return docs[doc_id]
```

## 3.3 리소스 접근 (Accessing Resources)

**한 줄 요약:** 클라이언트가 리소스를 읽어 와 파싱하는 부분. mime_type 보고 JSON이면 파싱, 아니면 텍스트.

**쉬운 설명**
- `read_resource(uri)` → `session().read_resource(AnyUrl(uri))` 로 서버에 요청.
- 결과의 `contents[0]`(첫 리소스)을 꺼내 `mime_type` 확인:
  - `application/json` → `json.loads(resource.text)`
  - 그 외 → `resource.text` 그대로
- 활용: CLI에서 화살표+스페이스로 문서 선택 → 선택한 내용이 **자동으로 프롬프트에 포함** → 채팅 중 굳이 도구로 문서를 읽을 필요가 없어짐.
- 의존성: `json`, `pydantic.AnyUrl`.

**핵심 코드**
```python
from pydantic import AnyUrl
import json

async def read_resource(self, uri: str):
    result = await self.session().read_resource(AnyUrl(uri))
    resource = result.contents[0]
    if isinstance(resource, types.TextResourceContents):
        if resource.mimeType == "application/json":
            return json.loads(resource.text)
        return resource.text
```

## 3.4 프롬프트 정의 (Defining Prompts)

**한 줄 요약:** Prompts = 서버가 제공하는 **검증된 프롬프트 템플릿**. 사용자가 슬래시 명령(`/format`)으로 호출.

**쉬운 설명**
- 서버 제작자가 그 도메인에 맞는 **고품질 프롬프트**를 미리 작성해 노출 → 사용자가 직접 프롬프트를 짤 필요 없음.
- `@mcp.prompt(name, description)` + 인자(예: 문서 ID) → **메시지 리스트**(user/assistant) 반환 → Claude에 직접 전달.

**핵심 코드**
```python
from mcp.server.fastmcp.prompts import base

@mcp.prompt(name="format", description="Rewrites the contents of the document in Markdown format.")
def format_document(doc_id: str = Field(description="Id of the document to format")) -> list[base.Message]:
    prompt = f"""... 문서 {doc_id} 를 마크다운으로 재작성 ... 'edit_document' 툴로 편집 ..."""
    return [base.UserMessage(prompt)]
```

**워크플로:** `/format` 입력 → 문서 선택 → 서버가 전용 프롬프트 반환 → 클라이언트가 Claude에 전달 → Claude가 도구로 읽고·재작성·저장.

**cli_project 연결:** `mcp_server.py`의 TODO "prompt to rewrite a doc in markdown"(+ summarize). `cli_chat.py`의 `_process_command`가 `/명령어`를 받아 이 프롬프트를 가져온다.

## 3.5 클라이언트의 프롬프트 (Prompts in the Client)

**한 줄 요약:** 클라이언트 쪽에서 프롬프트 목록·가져오기를 구현. 인자를 넘기면 서버가 템플릿에 끼워 넣어 돌려준다.

**쉬운 설명**
- `list_prompts` → `session().list_prompts()` 의 `.prompts`
- `get_prompt(name, args)` → `session().get_prompt(name, args)` 의 `.messages`
- 흐름: 클라이언트가 이름으로 프롬프트 요청 + 인자 전달 → 서버가 인자를 템플릿에 **보간(interpolate)** → 완성된 메시지 반환 → AI 입력으로 사용.

**핵심 코드**
```python
async def list_prompts(self) -> list[types.Prompt]:
    result = await self.session().list_prompts()
    return result.prompts

async def get_prompt(self, prompt_name, args: dict[str, str]):
    result = await self.session().get_prompt(prompt_name, args)
    return result.messages
```

**cli_project 연결:** `mcp_client.py`의 `list_prompts`/`get_prompt` TODO. `/format report.pdf` → 문서 ID가 프롬프트에 삽입되어 Claude로 전달.

# 섹션 4. 정리 (Wrap Up)

## 4.1 MCP 리뷰 — 3대 프리미티브 (MCP Review)

**한 줄 요약:** Tools·Resources·Prompts는 "누가 주도하느냐"로 갈린다 — 모델 / 앱 / 사용자.

| 프리미티브 | 제어 주체 | 누구를 위해 | 용도 / 예시 |
|---|---|---|---|
| **Tools** | **모델(Claude)** 이 실행 시점 결정 | 모델 | Claude에 능력 추가 (예: 계산용 JS 실행) |
| **Resources** | **앱 코드**가 가져올 시점 결정 | 앱 | 데이터를 앱으로 (UI 표시·프롬프트 보강, 예: 자동완성·Google Drive 문서 목록) |
| **Prompts** | **사용자** 행동(버튼·슬래시 명령)으로 발동 | 사용자 | 정해진 워크플로 (예: 채팅 시작 버튼) |

**고를 때:** Claude 능력 필요 → Tools / 앱 데이터 필요 → Resources / 사용자 워크플로 필요 → Prompts.

**실제 예:** Claude 채팅 시작 버튼 = Prompts, Google Drive 문서 선택 = Resources, 코드 실행 = Tools.

## 한 장 요약

| 섹션 | 레슨 | 핵심 |
|---|---|---|
| 1 | MCP란 / 클라이언트 | MCP = 도구를 서버로 분리한 표준, 클라이언트는 중개자 |
| 2 | 설정 / 도구 / Inspector | `@mcp.tool`로 도구 정의, `mcp dev`로 브라우저 테스트 |
| 3 | 클라이언트 / 리소스 / 프롬프트 | `list_tools`·`call_tool`·`read_resource`·`get_prompt` = 세션 래퍼 |
| 4 | 리뷰 | Tools=모델 / Resources=앱 / Prompts=사용자 |

**전체 한 문장:** MCP 서버에 Tools·Resources·Prompts를 정의하고, 클라이언트(세션 래퍼)로 그것들을 호출해 Claude와 연결한다. tool calling 루프는 그대로, 도구의 정의·실행만 별도 서버로 표준화한 것.
