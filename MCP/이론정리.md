# MCP 스터디 이론 정리 (REST API → Tool Calling → MCP)

> 메일/공유용 이론 정리. 흐름: **REST API(기능 노출) → Tool Calling(LLM이 사용) → MCP(연결 표준화)**
> ※ 앞 단계가 다음 단계의 토대. 실습 3개 모두 로컬(FastAPI, Ollama)에서 API 키 없이 동작.
> 각 개념의 코드 위치는 [examples/이론-코드-위치.md](examples/이론-코드-위치.md) 참고.

---

## 1. REST API / FastAPI

**■ REST API**
- 정의: 기능을 외부에 노출하는 표준 방식 (요청 → 응답)
- HTTP 위에서 동작하는 설계 방식 (REST 자체는 HTTP를 빌려 씀)
- 메서드 = CRUD: GET(조회) / POST(생성) / PUT·PATCH(수정) / DELETE(삭제)
- 상태 코드: 200 성공 / 201 생성 / 404 없음 / 422 검증실패 / 500 서버오류
- 데이터: JSON, URL은 리소스 중심 (/todos/{id})
- 엔드포인트(endpoint): 요청을 받는 [메서드 + 경로] 조합 (예: POST /todos, GET /todos/{id})
  · 같은 경로라도 메서드가 다르면 다른 엔드포인트 (GET /todos ≠ POST /todos)
  · FastAPI에서는 `@app.post("/todos")` 데코레이터 하나 = 엔드포인트 하나
  · 참고: REST는 엔드포인트가 여러 개(기능마다 URL), MCP는 엔드포인트 하나(/mcp)에 method로 구분

```
[예제] 요청/응답
요청:  GET /todos/5 HTTP/1.1      ← "GET /todos/5" 가 엔드포인트 (메서드+경로)
       │   │                       GET=조회, /todos/5=5번 할일
응답:  200 OK                      ← 상태코드(성공)
       { "id": 5, "title": "MCP 공부", "done": false }   ← 응답 본문(JSON)
```

**■ HTTP 헤더** (REST 전용 아님 — HTTP 기능을 REST가 그대로 사용)
- 정의: 요청/응답에 붙는 부가정보 (형식: Key: Value)
- 공통: Content-Type(본문 형식), Content-Length(크기)
- 요청: Authorization(인증), Accept(받을 형식), User-Agent, Cookie, Host
- 응답: Set-Cookie, Location, Cache-Control, Access-Control-Allow-Origin(CORS)

```
[예제] 헤더가 붙은 요청
POST /todos HTTP/1.1                 ← 엔드포인트 (POST=생성, /todos=할일목록)
Content-Type: application/json       ← 헤더: 본문이 JSON 형식이다
Authorization: Bearer eyJhbGc...     ← 헤더: 인증 토큰 (내가 누구인지)

{ "title": "MCP 공부" }              ← 요청 본문(만들 데이터)
```

**■ 인증 (Authentication)** — Authorization 헤더에 인증정보를 실어 보냄
- API Key: 발급 키 첨부 (헤더 X-API-Key 등). 단순, 서비스 식별용
- Bearer Token: `Authorization: Bearer <토큰>`. 로그인 후 발급, 가장 흔함
- JWT: Bearer의 한 종류. 토큰에 사용자정보·만료 포함 → DB조회 없이 검증
- OAuth 2.0: 제3자 위임 인증(예: 구글 로그인). Access/Refresh 토큰
- Basic Auth: ID:PW를 Base64 인코딩. 취약 → HTTPS 필수, 요즘 거의 안 씀
- 포인트: 키는 코드에 직접 X → .env 분리 + .gitignore (3번 보안과 연결)

**■ FastAPI**
- 파이썬 API 프레임워크
- 타입힌트 + Pydantic → 요청 자동 검증 (실패 시 자동 422)
- /docs (Swagger UI) → 브라우저에서 바로 테스트

```python
[예제] 최소 코드
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

# 요청 본문의 형태를 정의 (Pydantic) → FastAPI가 자동 검증해줌
class Todo(BaseModel):
    title: str            # 필수
    done: bool = False    # 기본값 False

# ↓ @app.post("/todos") 이 한 줄이 "엔드포인트 하나" (POST + /todos 경로)
@app.post("/todos", status_code=201)   # 생성 (201=만들어짐)
def create(todo: Todo):                # todo = 요청 본문이 자동으로 담김
    return {"id": 1, **todo.model_dump()}

# ↓ 또 다른 엔드포인트 (GET + /todos/{todo_id})
@app.get("/todos/{todo_id}")           # 조회
def read(todo_id: int):                # {todo_id} 값이 함수 인자로 자동 전달
    return {"id": todo_id}

# 실행:  fastapi dev main.py   →  http://127.0.0.1:8000/docs (브라우저에서 눌러보기)
```

**■ 다음 연결**
- FastAPI의 openapi.json ≈ 2번 tool 스키마
- 사람이 Swagger로 누르던 걸, 2번부터 LLM이 대신 누름

## 2. LLM Tool Calling

**■ 개념**
- LLM은 기본적으로 '말'만 함 → 도구를 주면 "이 도구 실행해줘" 요청 가능
- 실행은 내 코드가, 결과를 모델에 반환하면 모델이 최종 답 생성

**■ 핵심 사이클 (agentic loop)**
1. 도구 스키마 정의 (이름·설명·파라미터)
2. 모델 호출 → 도구 실행 요청
3. 함수 실행
4. 결과를 모델에 반환
5. 도구 없이 답하면 종료, 아니면 2로 반복
- → 이 반복이 '에이전트'의 본질

```python
[예제] 도구 스키마 + 수동 루프 (핵심만)
TOOLS = [{"type": "function", "function": {
    "name": "get_weather",
    "description": "도시의 현재 날씨를 조회한다.",
    "parameters": {"type": "object",
        "properties": {"city": {"type": "string"}}, "required": ["city"]}}}]

while True:
    resp = ollama.chat(model="qwen2.5", messages=messages, tools=TOOLS)
    msg = resp["message"]
    messages.append(msg)
    if not msg.get("tool_calls"):
        print(msg["content"]); break            # 도구 없으면 종료
    for tc in msg["tool_calls"]:                 # 도구 실행 후 결과 반환
        result = FUNCS[tc["function"]["name"]](**tc["function"]["arguments"])
        messages.append({"role": "tool", "content": str(result)})
```

**■ 포인트**
- 모델은 도구의 description 보고 사용 판단 → 설명 품질이 정확도 좌우

**■ 다음 연결**
- 지금: 도구를 내 코드 안에 정의
- 3번(MCP): 도구 정의·실행을 별도 서버로 분리·표준화
- 루프 자체는 동일, 실행 위치만 내부 → 외부 서버

## 3. MCP (Model Context Protocol)

**■ 정의**
- AI를 외부 도구·데이터에 잇는 오픈 표준 ("AI의 USB-C")
- N×M 문제(M모델 × N도구 개별 연동) → 한 번 만들면 재사용

**■ 3요소**
- Host: 사용자 + LLM을 담은 앱 (지휘관)
- Client: Host 안에서 서버와 1:1 통신하는 중개자
- Server: 실제 도구·데이터 제공

**■ 서버 3대 기능 (프리미티브)**
- Tools: 실행 (모델이 호출)
- Resources: 읽기 (앱이 가져옴)
- Prompts: 재사용 템플릿 (사용자가 호출)

```python
[예제] MCP 서버 (FastMCP)
from mcp.server.fastmcp import FastMCP
mcp = FastMCP("weather")

@mcp.tool()                              # 도구
def get_weather(city: str) -> str:
    return f"{city}: 맑음, 24도"

@mcp.resource("docs://list")             # 리소스
def list_docs() -> list[str]:
    return ["a.md", "b.md"]

mcp.run(transport="stdio")
```

**■ 통신 방식 (2가지)**
- stdio: 로컬 서버와 직접 통신
- Streamable HTTP: 원격 서버와 HTTP 통신
- ※ HTTP 위에서 동작하지만 REST 아님 → 메시지 규약은 JSON-RPC (HTTP 토대만 공유)

**■ 인증**
- 원격 MCP 서버: Bearer 토큰 / OAuth 2.0 (REST API와 동일)

**■ 보안**
- 위협: 민감데이터 노출 / 무단 명령 실행 / 키·토큰 탈취
- 대응: API 키 .env 분리 + .gitignore / 최소 권한 / 명령 필터링

## [부록] MCP vs Skill

**■ 한 줄 차이**
- MCP: 외부 도구·데이터에 "연결"하는 표준 (무엇에 연결하나)
- Skill: 특정 작업의 "절차·전문지식"을 Claude에 주입 (어떻게 하나)

**■ MCP**
- 성격: 통신 프로토콜 (서버 ↔ 클라이언트)
- 제공: Tools / Resources / Prompts
- 형태: 별도 서버 (stdio / HTTP), 코드로 된 도구

**■ Skill (Claude Agent Skills)**
- 성격: 지시문 묶음 (폴더 = SKILL.md + 스크립트 + 참고파일)
- 제공: "이 작업은 이렇게 해라"는 방법·노하우
- 형태: 파일(폴더), 필요할 때만 로드 (progressive disclosure → 토큰 절약)

```markdown
[예제] SKILL.md 최소 형태
---
name: weekly-report
description: 주간 보고서를 회사 양식으로 작성. "주간보고" 요청 시 사용.
---
# 주간 보고서 작성
1. 이번 주 GitHub 커밋·PR 요약
2. 양식: 이번 주 한 일 / 다음 주 계획 / 이슈
3. 개조식, 3줄 이내로 간결히
```

**■ 비교**

| | MCP | Skill |
|---|---|---|
| 형태 | 파이썬 서버 코드 | 마크다운 지시문 |
| 하는 일 | 도구 실행·데이터 제공 | 작업 방법 안내 |
| 예 | GitHub API 호출 | 그 결과로 보고서 쓰는 법 |

→ MCP = "코드로 된 도구", Skill = "글로 된 사용설명서". 경쟁 아니라 상호보완.
